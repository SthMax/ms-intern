Description
基于大模型的指标异动归因分析方法、系统、设备和介质
技术领域
本发明涉及计算机技术领域，特别涉及一种基于大模型的指标异动归因分析方法、系统、设备和介质。
背景技术
在对业务指标异动进行归因分析时，现有技术方案存在显著局限：一方面，系统分析维度固化，通常采用预设的静态模型，无法根据不同的分析主体（如渠道、产品或品类）智能切换分析视角和下钻路径，导致分析灵活性差、深度不足；另一方面，缺乏自然语言交互能力，业务人员必须掌握专业参数和数据结构才能发起复杂查询，使用门槛过高，严重制约了分析效率与决策敏捷性。
针对现有技术中存在的归因分析维度固化且缺乏自然语言交互能力而导致的归因分析灵活性不足与使用门槛高的技术问题，目前尚未存在有效的解决方案。
发明内容
本发明的目的在于提供一种基于大模型的指标异动归因分析方法、系统、设备和介质，能够解决现有技术中存在的归因分析维度固化且缺乏自然语言交互能力而导致的归因分析灵活性不足与使用门槛高的技术问题。

步骤S1，基于预置的大语言模型，接收并解析用户输入的自然语言问题，以获得结构化的归因意图；其中，所述归因意图包括：目标归因主体、所述目标归因主体所属的目标主体类型、目标归因时间和发生异动的目标业务指标。
目标归因主体指需要进行分析的具体对象，通常是一个名称或代码。目标主体类型指上述目标归因主体所属的类别。预定义了几种主体类型，例如：渠道类型、产品类型和品类类型，其中，渠道类型对应销售机构或平台。目标归因时间指自然语言问题中指明的时间点。发生异动的目标业务指标指用户所关心的、发生变化的量化指标。
比如，自然语言问题为：请分析一下基金代码164701在去年九月末相比前年同期规模变化的原因。解析后的结构化归因意图包括：“目标归因主体：164701”、“目标主体类型：产品”、“目标归因时间1：2025年9月30日”、“目标归因时间2：2024年9月30日”、“目标业务指标：规模”。再比如：自然语言问题为：请分析一下毛巾标识码M506在今年九月份相比前年同期规模变化的原因。解析后的结构化归因意图包括：“目标归因主体：M506”、“目标主体类型：产品”、“目标归因时间1：2025年9月1日”、“目标归因时间2：2024年9月30日”、“目标业务指标：规模”。
本步骤通过集成预训练的大语言模型（Large Language Model，LLM），将用户以自然语言提出的、非结构化的业务问题，智能地解析为计算机可识别和处理的结构化归因意图，取代了传统系统中繁琐的手动参数配置过程，是实现归因分析自动化和智能化的关键步骤。
需要说明的是，将自然语言问题输入大语言模型可以是将包含自然语言问题的提示词输入至大语言模型。比如，系统根据预定义的模板，构建提示词，该提示词通常由以下部分组成：a.系统提示，用于规定大语言模型需要扮演的角色、需要遵循的规则以及输出的格式；b.输入原始的自然语言问题；c.输出格式示例，用于明确要求大语言模型以指定的结构化格式输出，并给出示例，以指导模型如何抽取和归类信息。
例如，你是一个专业的基金业务归因分析助手，请将用户的自然语言问题解析为以下JSON格式的结构化查询。请务必从问题中识别并提取：
1）`target_subject`:归因主体，具体要分析的产品、渠道或品类的名称或代码。
2）`subject_type`:主体类型，比如是‘product’（产品）、‘channel’（渠道）、‘category’（品类）中的一个。
3）`time_range`:归因时间，包含两个时间点`time_point_1`和`time_point_2`的对象，请将其解析为‘YYYY-MM-DD’格式的字符串。`time_point_1`通常是报告期的时间，`time_point_2`是基期的时间。
4）`target_metric`:发生异动的业务指标，如‘规模’。
请严格按此JSON格式输出，不要添加任何解释。

步骤S2，从预置的框架库中配置出与所述目标主体类型关联的目标归因分析框架；其中，所述目标归因分析框架包括：至少一个目标归因分析项和每个目标归因分析项关联的至少一个计算对象和至少一个归因算法。
在本实施例中，框架库是一个预定义的知识库，目的在于将归因分析的业务逻辑与执行代码相分离。框架库中并非存储固定的分析程序，而是存储了可组装的、面向不同业务场景的分析组件及其组织规则。具体地，框架库中预定义了多种归因分析项，每个归因分析项代表一类特定的分析任务，例如，维度归因分析项为维度贡献度分析，因子归因分析项为因子分解分析等。每个归因分析项关联一套实现该分析所必需的计算对象以及至少一个归因算法。比如，维度归因分析项关联的计算对象构成了按预定业务层级展开的下钻分析路径，每个计算对象为该下钻分析路径上的一个维度节点，因子归因分析项所关联的计算对象为因子模型。比如，维度归因分析项中的计算对象可以分别是省份、城市、品类、产品。归因算法为贡献度计算算法、因子分解算法、GINI系数归因分析算法、JS（Jensen-Shannon）散度归因分析算法等。此外，框架库内还预置了明确的配置逻辑，该逻辑建立了主体类型与一套特定的归因分析项集合之间的映射关系。当系统接收到归因意图中的目标主体类型后，便依据此映射逻辑，从框架库中自动选取出与该目标主体类型相匹配的所有归因分析项，选取出的每个归因分析项作为本次分析的一个目标归因分析项。同时，系统会同步获取每个被选中的目标归因分析项所关联的计算对象与归因算法。

具体地，与目标主体类型关联的目标归因分析项存在一个或多个。对于每个目标归因分析项，均需确定出与目标主体类型和目标归因分析项同时关联的所有归因算法，且与目标主体类型和目标归因分析项同时关联的归因算法存在一个或多个。同样的，对于每个目标归因分析项，均需确定出与目标归因主体/目标主体类型和目标归因分析项同时关联的所有计算对象，且与目标归因主体和目标归因分析项同时关联的计算对象存在一个或多个，与目标主体类型和目标归因分析项同时关联的计算对象也存在一个或多个。
可选地，归因分析项为维度归因分析项、因子归因分析项、专项归因分析项，主体类型为渠道、产品或者品类。当所述目标归因分析项为维度归因分析项时，维度归因分析项关联的计算对象为该维度归因分析项的下钻路径中的维度节点，且维度归因分析项关联的归因算法为贡献度归因算法。比如，该维度归因分析项用于基于贡献度归因算法计算各维度对总体规模变化的贡献度，并可自动选择归因下钻路径。当目标归因分析项为因子归因分析项时，因子归因分析项关联的计算对象为因子分解模型，因子分解模型将目标业务指标表征为至少两个因子的乘积，因子归因分析项关联的归因算法为因子分解算法。当目标归因分析项为专项归因分析项时，该专项归因指标项关联的归因算法为JS散度归因算法和/或GINI系数归因算法，专项归因分析项关联的计算对象为结构性评估目标，该结构性评估目标包括用于评估渠道结构稳定性的渠道结构分布和/或用于评估区域集中度的区域变化量分布，其中，渠道结构分布表征为各渠道在目标归因时间所确定的时间范围内的规模占比所构成的集合，区域变化量分布表征为各区域在目标归因时间所确定的时间范围内的规模变化量所构成的集合；其中，JS散度归因算法用于对渠道结构分布进行分析，GINI系数归因算法用于对区域变化量分布进行分析。
可选地，当目标主体类型为渠道类型时，关联的目标归因分析项为维度归因分析项和因子归因分析项；当目标主体类型为产品或品类时，关联的目标归因分析项为维度归因分析项、因子归因分析项和专项归因分析项。当目标主体类型为渠道类型时，目标归因主体为银行时的维度归因分析项关联的维度节点数量大于目标归因主体为非银行时的维度归因分析项关联的维度节点数量。比如，目标归因主体为银行时的维度归因分析项关联的维度节点为：省份、城市、品类和产品；目标归因主体为非银行时的维度归因分析项关联的维度节点为：品类和产品。
本实施例基于实体以及实体关系建模的框架库配置流程，实现了分析策略的智能化动态适配。系统依据解析出的目标主体类型，能够自动从预置的框架库中，通过查询预设的实体关系，实时组装出与目标主体类型高度匹配的、包含完整分析项、计算对象及归因分析算法的目标归因分析框架。这一过程无需人工预定义或硬编码针对特定归因主体的固定分析流程，使得同一套系统能够自动理解并适配不同归因主体。例如，对于渠道类型的主体，系统自动适配侧重于地理维度和结构稳定性的分析组合；对于产品类型的主体，则自动适配侧重于净值份额因子及渠道来源的分析组合。基于该配置，有效解决了传统方法分析维度固化、切换不灵活的难题，显著提升了系统应对多样化、场景化分析需求的自动化水平和智能化程度。
