# 面向mentor和量化部门的案例平衡补查 — 2026-09-09

读者已明确为实习mentor及量化部门同事。现有方案若反复使用MENTOR、Index-Hub、SLAG、Label Horizon，易方达确实会占较大篇幅；这是公开资料检索和披露深度的偏斜，不能推导其他基金没有相关项目或技术落后。

这轮补查后的结论：**非易方达案例中，南方已有4分应用材料，工银瑞信新增两条可到4分的量化技术方案；汇添富找到接近4分的方案，但原件/公式缺口还未补齐。** 报告可以进一步平衡，暂不为凑公司数量提高其他案例分数。

## 2. 工银瑞信为什么足以提高技术深度

**MCTS因子挖掘**，CN116562377A，2023-08-08公布。物理PDF第14–26页（段落0068–0231）完整展开方法：

- 根节点用一元算子与初始特征构成二维盘面；叶节点有连续算盘面及“聚合算子×二元算子×新特征”盘面，槽点标记是否已扩展。第18页给出表达式逐级合成示例。
- 选择仍可扩展且评分最高的节点；在盘面中抽取槽点；沿路径计算因子、排序，并与基准排名计算回报；判断扩展是否有效，回传更新访问次数和改进记录。
- 第26页给出基于回报、开发能力、勘探能力的加权评分公式及可调权重。这里的回传是搜索树统计更新，不能误写成LLM梯度训练。
- MCTS调度在Host端，因子合成/排序回报的部分计算在Device端；明确一元、二元、聚合操作的分工，而不仅是“用了GPU”。

它适合作为**公式化因子自动搜索的传统算法基线**，与LLM生成因子形成方法比较。可讨论搜索空间、算子有效性、表达式复杂度、重复因子、搜索预算和样本外验证。4分适用于复建这一有边界的搜索原型，原数据、具体经济目标、完整收益评价和代码仍未公开；不能把文中的“回报值”直接解释为组合投资收益。

**债券违约预测**，CN114676932A，2022-06-28公布。物理PDF第14–17页（0120–0168段）给出数据源类别、处理流程、LightGBM基分类器、Self-Paced Ensemble迭代公式、模型选择和服务接口。它与量化风险建模直接相关，也能为后续模型验证部分提供具体对象。

此方案自身也有值得讨论的复核点：使用随机5折选择模型，面向未来违约预测时须追加时间顺序和发行人隔离检查；训练数据使用预测年份前两年财报的示例，仍须落实实际披露日期。原文把调参所用留出折称为测试集，不能直接作为最终独立测试。**流程披露完整，并不意味着评价设计已满足我们的所有要求。**

## 3. 汇添富的材料能补什么，还差什么

久期估算方案有具体输入、回归约束、衰减参数0.8、数据缓存与线程池、以上一日系数作初值等细节，比只有“AI风控平台”的介绍更接近可重建方法。不过Google镜像明确显示`patent-image-not-available`，缺失的原式不能靠常识补齐；本轮阅读副本逐处保留缺图提示。

规模异动归因给到`target_subject`、`subject_type`、`time_range`、`target_metric`等字段和JSON Prompt；框架库通过YAML/JSON/XML配置实体关系，动态选择维度/因子/专项分析，再生成多段报告。可借鉴的是**LLM负责意图及表达、确定性引擎负责计算**的分工。实例中相对日期有不一致，最终指标算法亦需补核。

另发现大模型自动评测申请CN122021937A的说明书镜像，描述按上下文选择指标、裁判模型、分项评分、日志和HTML/CSV/JSON输出。暂留[检索存档](../audits/2026-09-09-case-diversity/CN122021937A/retrieval.json)，未计为已核4分：没有完整评分Prompt/权重/测试集与人工一致性验证，不能把“自动评分”直接等同可靠验证。

用于生成组合调整信息的CN121961741A主要详细披露CDC/Kafka/组合分区/实时持仓计算，而优化器仍是概括描述；不能把数据工程的详细程度当成完整组合优化算法。自然语言查询CN122309540A本轮只有摘要报道且镜像404，也未据此提分。

## 4. 报告怎样减少易方达集中度

建议四个专题继续保留，但每章按技术问题挑主案例：

| 专题 | 建议分配 |
|---|---|
| 投研推理 | 易方达MENTOR作一条主案例；天弘等作应用场景对照，注明3分材料限制 |
| 受控数据查询 | 南方NL2SQL作主案例；易方达Index-Hub收至对照框或附录 |
| 知识问答／合规与验证 | 鹏华作公司应用对照，汇添富评测方案作为待补技术候选；这一章暂不假定已有完整4分案例 |
| 量化 | 工银瑞信MCTS因子搜索，与易方达标签期限优化作不同方法的主对照；工银信用模型及汇添富久期作风险侧备选；微软RD-Agent为外部技术参照 |

易方达保留其最有价值的一至两条技术主案例即可，其余材料放附录。面向量化同事，正文优先回答：输入/标签是什么、核心算法做了什么、怎样验证、结果有什么边界、哪些环节值得自己尝试。用3分材料说明场景，用4分材料展开技术，不要求每个公司每个专题都有同样深度。
